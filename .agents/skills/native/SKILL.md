# Native

Use when working in `apps/native`.

## Required reading

- [Expo Style Guide](../../../docs/expo/style-guide/index.md)
  - [Project Structure](../../../docs/expo/style-guide/project-structure.md) — the files Expo owns, routes, screens, `src/shared/`.
  - [Components](../../../docs/expo/style-guide/components.md) — a folder per component, theme roles, the palette, `testID`.
  - [Hooks](../../../docs/expo/style-guide/hooks.md) — a folder per hook, colocated or shared.
  - [Context](../../../docs/expo/style-guide/context.md) — a folder per context, providers in the root layout.
  - [State](../../../docs/expo/style-guide/state.md) — Zustand stores through `createAppStore`, no `useState`.
  - [Testing](../../../docs/expo/style-guide/testing.md) — Jest on `jest-expo`, fake timers, `mockFetch`, the helpers.
- [Placement Rule](../../../docs/style-guide/placement-rule.md) — where a unit lives.
- [Imports](../../../docs/style-guide/imports.md) — `@/`, `./`, never `../`.
- [i18n](../../../docs/style-guide/i18n.md) — one JSON file per domain, tests assert on keys.
- The testing guides: [Test Organization](../../../docs/style-guide/test-organization.md), [Test Quality](../../../docs/style-guide/test-quality.md), [Testing Patterns](../../../docs/style-guide/testing-patterns.md) and the [Expo Testing Patterns](../../../docs/expo/style-guide/testing-patterns.md).
- [TypeScript Conventions](../../../docs/typescript/conventions.md) — type prefixes, no single-letter names.

Before writing a test, also read the [`testing`](../testing/SKILL.md) skill.

## Key rules

1. The files Expo owns — `expo-router/entry`, `src/app/_layout.tsx`, `src/app/(tabs)/_layout.tsx` and the route files in `src/app/(tabs)/` — stay bare.
2. A route file renders its screen and nothing else.
3. `ios/` and `android/` are generated by `expo prebuild` and never committed; a native change goes through `app.config.ts`.
4. Screens live in `src/screens/<screen>/index.tsx`; a piece one screen uses lives in its `components/` or `hooks/`; a piece several use lives in `src/shared/`.
5. `src/app/_layout.tsx` wires i18n, the status bar and the splash hold; a provider is defined under `src/shared/` and wired there.
6. Every component, hook and context is a folder with `index.ts` or `index.tsx`; sibling files are its sub-components, in kebab-case; no bare `.tsx` in `screens/`, `shared/components/` or `shared/`.
7. Build with React Native primitives and `StyleSheet`, reusing `ScreenContainer`, `Card`, `ListRow`, `PrimaryButton` and `Icon` before writing a new component.
8. Every colour, spacing, radius and font size is a role from `src/shared/theme`; every colour value is in `src/shared/theme/lib/palette.json`, and lint refuses a hex or `rgb()` literal anywhere else.
9. Every component has a `testID`.
10. A hook over a platform API stays small, so a test mocks that one wrapper; a helper never navigates or has side effects.
11. State lives in Zustand stores, one per concern, made with `createAppStore(scope, initializer)` from `src/shared/zustand/`, never `create`; the first goes in `src/shared/stores/<store>/index.ts`.
12. A `member` store is cleared at sign-out by `resetMemberStores()`; a `device` store is kept; `resetAllStores()` runs before each test.
13. No `useState` or `useReducer` in screens, components or hooks; `useApiVersion` is the one exception today.
14. A hook over a store is a view that selects, words errors with i18n and navigates; `useRef` holds only view handles and values that do not render.
15. Derived values are selectors, and state changes in actions because something happened, never in an effect watching a value.
16. Strings live in one JSON file per domain under `src/i18n/resources/en/`, with no `common.json`, and a screen loads its own with `useTranslation("<domain>")`.
17. Tests run on Jest with `jest-expo` and React Native Testing Library, and render the full tree, never shallow.
18. Fake timers are on for every test: advance once by the whole duration, and settle promises with `advanceTimersByTimeAsync(0)`, never a polling `waitFor`.
19. Press with `userEvent.press` by `testID`, fill a field with `userEvent.paste`, and use `userEvent.type` only when keystrokes matter.
20. Assert visible behaviour and i18n keys, never styles or translated text.
21. The network answers through `mockFetch` (`on`, `calls`, `cancelled`); a route test renders the stand-ins in `src/app/__mocks__/mock-screens.ts`, not the screens.
